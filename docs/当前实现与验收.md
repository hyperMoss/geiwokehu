# AI Growth Ops 当前实现与验收

更新：2026-09-26

## 已实现

现有 Next.js 工作台已从单一采集页扩展为五个页面：`/` 关键词采集、`/leads` 潜客筛选、`/customers` 客户管理、`/analytics/lead` 获客分析、`/integrations` 集成配置。Python 回环服务继续使用同一个 SQLite 文件，启动时自动创建新表并从已保存的评论回填潜客候选；无需清空历史数据。

评论入库后，后端按固定关键词规则生成 A/B/C 意向**提示**，聚合同一平台的匿名作者哈希，保留评论原文、规则依据、来源关键词和证据条数。无作者哈希时按评论 ID 单独保留候选，不按昵称合并。否定或广告表达不入潜客。规则结果需要人工复核；没有调用 AI 模型，也不推断联系方式。

运营可筛选、复核或排除潜客，再填写已核实的客户名称与资料转入客户。重复转入返回同一客户；客户可手动创建、搜索、修改生命周期状态和下次跟进时间，变更有本地事件记录。分析页提供 7/30/90 天的任务、素材、评论、潜客、高意向和转客户指标，以及漏斗和每日新增图；业务日期按 `Asia/Shanghai` 计算。

## 数据与接口

新增 `leads`、`customers`、`customer_events` 表；已有 `jobs`、`items`、`comments` 表继续使用。潜客和客户记录分别具有稳定 UUID。客户的 `source_lead_id` 唯一，保证同一潜客转换幂等；匿名作者哈希只用于同平台聚合，不能用来联系用户。

新增接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/leads?q=&level=&state=` | 潜客筛选 |
| PATCH | `/api/leads/:id` | 复核状态 |
| POST | `/api/leads/:id/convert` | 转客户 |
| GET/POST | `/api/customers` | 客户列表和手动创建 |
| GET/PATCH | `/api/customers/:id` | 客户详情、编辑及事件 |
| GET | `/api/analytics/lead?days=7\|30\|90` | 获客分析 |
| GET | `/api/integrations/capabilities` | 仅返回本机账号 Cookie 的已配置 / 未配置状态 |

Next.js Route Handlers 将请求转发至本机 Python 服务。开发服务器允许 `127.0.0.1` 访问开发资源，修复了在该地址打开页面时客户端脚本不执行的问题。

`/integrations` 只显示由本机 Python 服务提供的账号变量布尔状态（已配置 / 未配置），不会返回、显示、保存或写入 Cookie。用户需自行把 Cookie 配置到被忽略的 `.env.local`，然后重启 Python 服务；页面不会读取浏览器 Cookie、密码、个人资料或已有登录会话。

## 验证

- Python 单元测试 7 项通过，覆盖双平台离线导入、潜客聚合、排除规则、幂等转客户、状态和分析，以及 Cookie 状态脱敏。
- `npm run typecheck`、`npm run build` 通过。
- 使用临时 SQLite 数据库和回环 HTTP 服务完成“评论入库 → 潜客列表 → 两次转客户返回同一 ID → 客户状态修改 → 7 天统计”验收，不写入正式本地数据。
- 浏览器实查潜客、客户和分析页面；分析页指标加载完成，7/30 天切换可交互。

## 尚未实现

意向识别目前只是规则提示，没有 AI 模型、评分评估集或人工修订分数。客户库尚无成员权限、CSV 导入导出、可靠的手机号核验、飞书同步、成交详情。内容生成、发布、评论私信也仍在设计阶段。MediaCrawler 的真实平台采集仍需在具备依赖和账号 Cookie 的环境单独验收。当前回环服务无生产鉴权，不能直接暴露公网。
